## 2. Причины по каждой операции

### 2.1. `startLanding()` — 5.5 мс

```
gen 0.9 · poi 0.1 · deco 0.1 · sky 0 · surfGen 0.7   (по последнему прогону)
runs.start = 5.5 мс
```

Всё внутри функции — доли миллисекунды. Никакой синхронной генерации на сотни мс нет:
`surfGen` (залежи, флора, фауна, устье) укладывается в ~1 мс.

### 2.2. `enterSurface()` — 3.0 мс

```
sg.gen 1.2 (surfGen переиспользуется из G.land.pre)
sg.setup 0.6 · sg.lights 0 · sg.lines 0.6 · sg.say 0
runs.enter = 3.0 мс
```

`surfGen` не пересчитывается: `L.pre` уже посчитан в `startLanding`, ключ — тот же `tr`.
Свет (`lightsArrive`) и истории — доли мс.

### 2.3. `drawWorld()` в шахте — 5.5 мс

```
dg.frame 5.5 (dig3Frame) · dg.over 0 (dig3Over) · gw.{front,bloom,ov} = 0
```

`gpuWorld` (bloom/виньетка/зерно) — **0 мс**: bloom не виноват, и его снижать не нужно.
**«15 мс» — это `dw`**, а `dw` в `28-loop.js` оборачивает
`if(drew){ rackDraw(); drawWorld(); drawHitFx(); }`, то есть включает **`rackDraw()`**
(приборная стойка, `25d-instr-rack`) — отдельную подсистему, не входящую в цель.

## 6. Что осталось

1. **`rackDraw()` (`25d-instr-rack`) ~9 мс** — не входит в цель «drawWorld», но именно он делает
   `dw` = 15–16 мс. Отдельная подсистема приборной стойки; нужен свой профиль.
2. **2 красных браузерных сьюта** — предсуществующие (подтверждено на базе), вне этой задачи.
3. **Прогон в обычном окне** (не headless) не делался; по прошлым этапам окно давало те же цифры,
   но отдельного трейса окна нет.
