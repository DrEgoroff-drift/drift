## Режимы
- system — замерено (см. выше).
- surface, cave, belt, dig, base — НЕ замерено. Вход вызовом enterX() без игрового контекста падает: `Cannot read properties of null (reading 'tr' / 'p' / 'seed')`, `undefined (reading 'idx')` (enterSurface:7, enterCave:175, enterBelt:71, enterDig:51, enterBase:121 в src/). После падения prof() остаётся в system, поэтому цифры для этих режимов не относятся к ним.
  Вывод: это, вероятно, артефакт моего входа, а не игрока (игрок заходит через посадку/стыковку). Но проверить через реальный путь входа не успел.
- карта, посадка, пояс-бой (raid), homein — не замерено.

## Ограничения (что не сделано)
1. Вход в режимы — через реальный путь игрока (посадка/стыковка/гоцепт), не прямым enterX().
2. Утечки памяти за 5 минут: нужен замер heap (CDP HeapProfiler / performance.memory) — в этой сборке performance.memory недоступен.
3. GC-рывки: нужен долгий rAF-лог с отметкой кадров >16 мс и сравнение с GC-событиями (Tracing).
4. Тайминг 5 минут на прогон — времени не хватило в этой пробе.

## Предложение
- Добавить в тестовый стенд (drift-game.ru/dev не трогать) режимный вход через публичный API (gotoSector / посадка), чтобы prof() шёл по каждому режиму.
- Для памяти — отдельный сценарий 5 мин с замером G-объектов и DOM-узлов, снятие heap-снимков в начале/середине/конце.
- Проверить, почему enterX() без контекста падает, — если это вызывают из меню, это уже баг входа (сообщить отдельно).
